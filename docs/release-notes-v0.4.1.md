# v0.4.1 — 无人值守额度可调 + 只读标签补齐重放

## 为什么发这一版

0.4.0 之后暴露出两个具体问题，都来自实际使用：

1. **20 分钟 / 30 次动作写死了。** 一条正常的后台导出流程经常超过 30 个动作，跑到一半就回到逐次批准，定时任务里没人点，任务卡住。用户只能把流程拆成三条，或者干脆不用无人值守。
2. **只读标签能被流程重放绕过。** `browser_click` / `browser_type` / 同标签 `browser_navigate` 都拒绝只读标签，但 `browser_demo_recipes { action: "run" }` 和 `browser_demonstrate { replay: true }` 直接走重放，没有这道检查。把一个标签设成只读，再跑一条保存的流程，仍然能在它上面点击。

## 改了什么

### 无人值守额度可调

设置 → 智能体增强 → 功能 → 浏览器 Agent 下新增：

- **授权时长（分钟）**：默认 20，范围 5–60
- **动作上限（次）**：默认 30，范围 10–200

规则没有变：只对流程录制时的站点生效，按次授权，不持久化，换站点 / 换会话无效，密码仍然停下等人，被拒立即撤销。变的只是这张通行证的额度从常量变成设置项。

输入夹取做在两层：设置页提交时夹一次，`resolveSettings` 读取时再夹一次，所以手改配置文件也绕不过范围。

### 只读标签覆盖重放

`browser_demo_recipes` 的 `run` 和 `browser_demonstrate` 的 `replay: true` 现在与直接操作一样先过 `TabScopeStore`：

- 检查发生在拉起浏览器、解析变量、发无人值守授权之前，被拒绝时什么都没发生；
- 复用同一条 `tab_read_only:` 拒绝文案，说明怎么解锁；
- 单测覆盖两条路径（流程重放、演示重放）。

## 影响

- 默认值不变，升级不改变现有行为；只有主动调过设置才生效。
- 只读标签多拦了一种写路径，这是收紧，不是放宽。
- 保存的流程文件、`lastRun`、授权结构都没有变化。

## 升级

```bash
dsh plugin --profile desktop add dsh-agent-enhancer@0.4.1
```

或在 Desktop「设置 → 插件」里更新后重启。
